# ProtEva Codex Handoff

This document records the frontend as inspected on 2026-10-16. It distinguishes implemented demo behavior from planned integrations. No AI or scientific backend is currently implemented.

The repository's package-manager signal is Bun: `bun.lock` is present and `bunfig.toml` sets `minimumReleaseAge = 86400` plus Lovable package exclusions. No npm, pnpm, or Yarn lockfile is present. `package.json` declares no `engines` field, and no `.nvmrc`, `.node-version`, or `.tool-versions` file was found. ## Initialization and Routing

- `src/start.ts` configures TanStack Start request middleware. It restores CSRF middleware for server functions and wraps unexpected request errors.
- `src/server.ts` is the server entry configured by `vite.config.ts`. It imports the TanStack Start server entry and normalizes certain swallowed SSR errors.
- `src/router.tsx` creates a TanStack Router with a React Query `QueryClient` in route context.
- `src/routes/__root.tsx` supplies document metadata, the root HTML shell, query provider, toaster, demo-sync hook, not-found and error boundaries. `/` renders without `AppShell`; all other paths render inside it.
- `src/routeTree.gen.ts` is generated by TanStack Router. Do not edit it manually.

## Current User Flows

### Experiment creation and demo execution

`src/routes/experiments.new.tsx` owns a four-step local-state wizard: sequence/name, target landscape, search settings, and review. It checks the sequence alphabet and minimum 20 residues, and requires name, objective text and target-state description before advancing. It warns about some omissions and search sizes but does not fully validate numeric bounds. FASTA upload reads a local file, drops lines beginning with `>`, strips whitespace and fills the sequence. The optional PDB picker stores only `file.name`; no bytes are uploaded. Launch calls `api.createExperiment` and navigates to the returned experiment.

In demo mode, `MockApiClient.createExperiment` creates an in-memory record and starts a timer-driven state machine (`queued`, `validating`, `sampling`, `evaluating`, `auditing`, `completed`). `buildCandidates`, `buildGenerationStats`, and `buildAgentEvents` create deterministic illustrative content. This is not a real genetic algorithm, Gemma execution, BioEmu job, or scientific evaluation. State is not persisted across page reloads or server restarts.

### Candidate ranking and charts

`useCandidates` calls the selected API client with filters. The mock filters by experiment, generation, mutation count, evaluation status, candidate ID and mutation text. The route applies client-side sorting. Candidate score and metrics are illustrative in demo mode. `ObjectiveChart` and `DiversityChart` render `GenerationStat[]` supplied by the API; no metric calculation occurs in the charts.

### Agent timeline

The `AGENTS` roster and scripted event list in `mock-data.ts` drive the agent views. The demo shows message, delegation, tool-call, result, warning and decision-shaped events, but these are static scripts, not inter-agent communication. UI copy discloses that no Gemma call occurs. Agent cards use static status/task descriptions; only event counts depend on the selected run.

### Exports and artifacts

Experiment Markdown and JSON reports are composed by `MockApiClient.exportExperiment`; JSON explicitly separates user inputs, settings, no actual measurements, demonstration values and limitations. `HttpApiClient.exportExperiment` instead requests `/experiments/{id}/export?format=...` and reads text. The experiment artifact table obtains artifact metadata through `getArtifacts`; selected downloads are assembled in the browser from the current experiment, candidates and events. Sampled structures are intentionally unavailable. Candidate and input sequence downloads use FASTA. No secure backend artifact storage/download flow exists yet.

## API Boundary and Integration Readiness

The `ProtEvaApi` interface is a useful seam. `MockApiClient` is the demo implementation; `HttpApiClient` is a thin JSON REST client. When a configured live request fails, the client throws and there is no mock fallback. Keep this property.

The current HTTP endpoint assumptions are `POST /experiments`, `GET /experiments`, `GET /experiments/{id}`, `GET /experiments/{id}/events`, `GET /candidates`, `GET /candidates/{id}`, `GET /experiments/{id}/artifacts`, `POST /experiments/{id}/cancel`, and `GET /experiments/{id}/export?format=...`. These are assumptions in the frontend, not an implemented backend contract.

Important changes needed before live results can fit accurately:

- `Experiment.simulated: true` in `src/lib/protein/types.ts` makes every experiment a demo by type. Replace it with an execution-mode plus result-provenance model; affected frontend files are itemized in `docs/api-contract.md`.
- `AppShell` always shows a demo badge. Report strings and several descriptions are demo-specific. They must be conditional on returned execution mode/provenance before live deployment.
- `useDemoSync` subscribes only to the mock singleton. HTTP data has no polling or event stream and can go stale after the initial fetch.
- The typed HTTP client uses unchecked `as T` response casts, offers no runtime schema validation, authentication, upload support, or artifact authorization, and does not normalize base URLs or encode path IDs.
- `getArtifacts` returns metadata, while downloads are mostly made from UI-held data. The backend must own authorization and artifact storage.
- The `referencePdbName` is metadata only; the actual file is discarded.
- `MockApiClient` is a module singleton with in-memory state. In an SSR process, shared server module state must not become a tenant/user data boundary.

## Tests and Gaps

`src/test/app-routing.test.tsx` has two tests: `/` resolves to the landing route and `/overview` resolves to the workbench route. `src/test/setup.ts` configures the Vitest environment. There are no tests for wizard validation, mock state transitions, candidate generation/filtering, report content, HTTP API behavior, failed-request behavior, uploads, accessibility or backend contracts.

At inspection time, `node_modules` was absent and Bun was not available. Prior `npm run build`, `npm run lint`, and `npm test` attempts failed at command resolution (`vite`, `eslint`, and `vitest` not found), so these are dependency/toolchain failures, not demonstrated source failures. `get_errors` also could not resolve `vite/client` or `vitest/globals` because dependencies were absent. Install with `bun install --frozen-lockfile`, then run `bun run build`, `bun run lint`, and `bun run test`.

## Not Implemented

The UI and mock demo are present; production integrations remain future work. See `docs/api-contract.md` and `docs/integration-roadmap.md` for proposed specifications, not implemented behavior.
